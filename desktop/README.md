# Loops Mac 客户端

正式代码位于本目录与 `../runtime/`；历史原型不包含在公开源码中。界面保持左侧 Loop 导航、中间对话与单次执行、右侧流程和运行记录。

## 当前能力与边界

- Electron + React 实际客户端，提供本机输入文件选择、试跑、停止、保存、历史结果与交付文件查看。
- 左右栏可拖动边缘调整宽度，双击恢复该栏默认宽度。切换 Loop 和重启后保留调整；缩小窗口时自动给对话区保留空间。聚焦分隔线后可用左右方向键微调，Shift 加快，Home/End 到达宽度边界，Enter 恢复默认。
- 新建使用独立创建页：居中引导、底部需求输入，输入与发送共用工作台组件；首次发送非空需求后才创建 Loop 和工作目录并进入对话与流程工作台，启动或反复点击新建不创建记录。工作目录统一默认在 ~/Loops/ 下创建，每个 Loop 使用独立子目录，不提供手动选择入口；历史目录不迁移。已有 Loop 在标题左侧显示目录图标，移入标题即时显示工作目录，移开即隐藏；键盘聚焦同样可查看，Esc 可关闭提示。点击标题打开目录。
- 左侧 Loop 的更多菜单支持重命名和删除，回收站支持恢复。重命名不改历史版本，后续 AI 更新保留员工指定的名称。删除保留定义、脚本、对话、版本、历史运行和交付文件，不清理工作目录或原始输入；运行中或 Loops AI 处理时不能删除。
- Loops AI 使用 Pi Agent Core 1.4.0 和 DeepSeek。通过工具检查项目、读取文件、生成或修改流程、读取失败证据、启动试跑和保存。
- 新流程使用通用结构化配置，自由决定步骤数量。每步保存任务、输入映射、执行配置、产出、完成条件和失败处理。展开步骤查看固定配置，运行命令在对应运行记录中查看。
- 支持 Codex、Python 脚本和直接命令。Codex 使用官方 `openai-codex==0.163.0`，相同工作目录与 session 可共享会话；Python 从统一上下文接收本步骤输入与产出路径。脚本源码与配置一起保存，详见 `../runtime/WORKFLOWS.md`。
- 每次运行固定配置、脚本和输入副本，使用独立工作目录。选用 Git 资料时建立独立 Git 工作区；普通流程不要求仓库。完成条件依据实际文件与命令退出码检查，失败按配置重试或返回指定步骤，达到上限保留失败证据。工程与业务流程统一使用通用执行器，旧七步定义不再支持，需重新搭建；历史文件和记录不自动删除。
- 保存与执行成功独立。保存时归档定义、资源配置、脚本与版本；历史运行继续保留原版本。重启后未完成执行标为中断，不自动重放外部提交。
- 结果来自真实 SDK、进程退出码、测试日志与文件，没有前端定时器推进或预设成功结果。

历史验证已覆盖本机 Codex 修复、真实 Pi + DeepSeek 自然语言搭建、通用流程试跑与保存恢复。手工流程、模型替身和真实服务结果需要如实区分；临时证据仅在本机保留。

**远程交付**：通用流程可通过明确配置的脚本和命令执行外部操作，不再内置工程专用的提交、GitHub 草稿 PR 与同输入 PR 复验路径。历史样例仅交付本地文件，没有创建或验收真实 PR。自动化任务现已支持 Python 定时与监听、多个已保存 Loop 串联及输出投递，仍没有云端常驻调度或发布使用端。

## 自动化任务

左侧“自动化任务”可以新建任务，也可从已保存 Loop 顶部的“自动化”进入。新建页与 Loop 共用对话输入组件；首次发送需求后创建独立任务，Loops AI 持续追问、搭建和调整，右侧同步展示流程。对话、草稿和模型会话均持久化，刷新或重启后可继续。输入映射和 Python 脚本放在可选的“流程配置”中查看和修改。定时、目录监听、webhook 都由输入脚本实现；平台管理生命周期、持久化队列、版本快照与回执。

可以通过对话要求保存、采样、试跑、启用或暂停，也可使用对应按钮。仅搭建或调整时不自动保存、启用或投递；试跑使用固定版本和真实输入。保存后也可先“测试输入”，再“运行样本”验证整个链路与真实投递；已有 Loop 产出后可单独试投递指定输出。支持启用、暂停、停止单次运行、核对后继续、删除与恢复。失败或不确定的投递不会声称成功；成功节点与目标在重试中保留。重启恢复来源和未开始队列，不自动重放中断的外部操作。

脚本接口、版本及本机连接配置见 [执行约定](../runtime/AUTOMATIONS.md)。每版脚本使用独立标准库 venv，不自动安装第三方依赖。关闭窗口继续后台运行，彻底退出或电脑休眠期间不执行；外部 webhook 需要可达入口。

真实服务脚本需先设置 `LOOPS_MODEL_CONFIG_DIR` 指向已配置模型的客户端数据目录；脚本通过 Electron 读取加密配置，不读取环境文件。`node scripts/live-automation-chat.mjs` 验证真实多轮对话、修改、保存、试跑、交付与重启继续，会消耗模型额度。`node scripts/live-automation-journey.mjs` 使用隔离目录、真实 Python 和本机真实 Pi + DeepSeek 验证采集、串联、投递与重启，会消耗模型额度。示例中的两个 Python Loop 为手工测试定义，不代表 Codex 或 AI 业务分析能力的新增验收。

双击 `scripts/open-latest.command` 可打开当前打包客户端，使用正常 Application Support 数据与项目现有本机模型配置，不进入验收数据库。

## 模型与本机配置

Loops AI 的模型和密钥统一在“设置 → 模型”管理，Codex 仍使用本机 Codex 登录，两者独立。

添加模型时，已配置的服务商直接复用已有密钥；自定义 OpenAI 兼容服务按规范化 API 地址区分。填写新密钥会更新同一服务下的所有模型。默认模型用于新对话，输入区可以切换当前使用的模型，并选择该模型支持的思考强度；各模型的强度分别保存，下一次回复生效。密钥通过 macOS 安全存储加密后保存到数据目录的 `models.json`，不会回传到页面状态或执行子进程。

升级时会将旧 `.env.local` 和此前保存的模型配置一次性迁入加密配置。迁移成功后不再读取 `.env.local` 或模型密钥环境变量，后续变更只通过设置操作。旧文件不会自动删除，以免影响其中的其他本机配置。迁移失败时保留原文件并报错，不记录迁移完成。

开发时使用 `npm run dev` 的 Electron 客户端管理密钥；浏览器预览不提供 macOS 安全存储。

## 本地开发

开发需要 Node.js 22.19+、Python 3.13。Git 资料需要 Git，使用 Codex 的步骤需要本机已登录 Codex。测试样例只使用 Python 标准库。正式项目需要自行准备其项目依赖；执行器不会自动安装任意依赖。

从 `runtime/` 执行：

```sh
sh setup.sh
.venv/bin/python -m unittest discover -s tests -v
```

从 `desktop/` 执行：

```sh
npm ci
npm run dev
```

`npm run dev` 启动原生 Mac 窗口。`npm run dev:browser` 单独启动用于界面检查的本地开发入口（4174端口）；浏览器与 Mac 默认数据目录不同。浏览器入口不提供原生文件选择与 Finder 打开目录。

开发运行数据在 `desktop/.local/`，正式应用默认使用 macOS Application Support。每个 Loop 自动创建独立工作目录：`draft/`、`versions/<版本>/`、`runs/<运行ID>/`。每次运行保留输入副本、定义、脚本、工作区、事件、步骤结果和实际检查记录，具体交付文件由流程定义决定。运行目录应保留，以便复查和更新已有 PR。

## 检查和真实试跑

```sh
# desktop/
npm test
npm run build
node scripts/live-generic-journey.mjs sales
node scripts/live-generic-journey.mjs engineering
```

`live-generic-journey.mjs` 使用真实 Pi、DeepSeek、Codex 与本地样例检查搭建、执行、失败反馈、业务反馈、换输入再执行和保存，会消耗模型额度。它可从保存的阶段继续，当前记录在 `.local/generic-acceptance-20261030`，不复用旧格式的验收状态。`sales` 仅运行 Python，`engineering` 调用真实 Codex，需在具备本机执行权限的环境中运行。两种样例统一使用 resources、inputDefaults 和按 ID 映射的运行输入。

长期测试保存在 `tests/`，真实服务检查命令见上文。`qa/` 仅用于本机临时检查，整体忽略，无需维护验收报告。

## 打包 Mac 应用

在 `runtime/` 下准备与许可清单对应的固定 Python 发行版：

```sh
sh setup-bundled-python.sh
```

然后从 `desktop/` 执行：

```sh
npm run build
npm run package:mac
```

输出为 `out/Loops-darwin-arm64/Loops.app`（当前机器为 Apple Silicon）。应用携带 Python、SDK 与固定 Codex 运行时。打包脚本从 requirements.lock 重新安装 Python 依赖，不复制开发虚拟环境；仅纳入客户端运行目录，并生成第三方许可清单。`Contents/Resources/legal/` 保存项目与依赖声明。当前为本机开发构建，尚未做开发者签名、公证、安装器与自动更新；第三方二进制声明核对尚未完成，不能作为公开安装包分发，见 [第三方组件清单](../THIRD_PARTY.md)。

可用 `LOOPS_PACKAGE_OUT` 指定隔离输出目录。打包后在 `desktop/` 执行 `npm run test:package -- /absolute/path/to/Loops.app`，可核对包内依赖与许可文件，并使用手工定义的 Python 流程验证执行、保存和重启恢复；不调用模型，不代表真实 AI 对话验收。

应用图标采用蓝底白色立体带状双回环，Dock、对话头像与网页标签共用 `public/assets/loops-icon.png`，Mac 打包使用 `assets/loops.icns`。设计源稿保存在 `design/app-icon/`；修改源稿后，在本目录执行 `swift scripts/export-icon.swift` 重新导出资源，再重新构建、打包。`design/drafts/icon-v2/` 是未采用的扁平几何尝试。

本版本依赖本机登录及项目授权，未承诺对不可信仓库提供完整的进程、网络和凭证隔离；Codex 使用其 workspace-write 沙箱和自动审批审查，项目测试命令由本地执行器按约定启动。面向组织部署前还需要完善权限配置和外部操作恢复。

签名、公证所需的团队、证书与本机凭证配置见 [Mac 分发说明](MAC_RELEASE.md)。

## 自定义 MCP 流程步骤

在“连接器 → 自定义连接器”添加 MCP 地址，或导入本地 `stdio` 配置并连接。随后直接告诉 Loops AI 要使用该服务完成什么任务；AI 会发现操作、查看参数并将它加入流程，无需修改客户端或为服务编写 Python 中转脚本。

流程保持 `schemaVersion: 2`，原有 Codex、Python、命令行与文件输出仍可使用。MCP 步骤的配置示例：

```json
{
  "execution": {
    "tool": "mcp",
    "connectorId": "my-service",
    "operation": "lookup",
    "arguments": {"query": "${inputs.query}"}
  },
  "outputs": [
    {"id": "data", "label": "查询结果", "kind": "value", "pointer": "/payload"}
  ]
}
```

`pointer` 使用 JSON Pointer，从统一连接器响应选取结果：`/payload` 是业务数据，`/result` 是原始 MCP 响应，`/links` 是候选链接列表，空字符串表示完整响应。字段缺失会使步骤失败；`null` 是有效值。后续步骤用完整引用 `${steps.lookup.outputs.data}` 接收原始 JSON 类型，Python 步骤通过 `LOOPS_CONTEXT.inputs` 接收。数据产出同时保存为 JSON 文件供查看；跨自动化节点交付时沿用文件契约。服务返回的文件链接不会被当作已经下载的本机文件。

搭建和保存时，执行服务记录所选工具的参数、返回与读写契约；执行前重新检查连接和工具契约，变化时需重新保存流程。未知读写影响需先评估，高风险操作沿用现有连接器限制。每次调用保存真实响应和状态；写操作一旦发起，本次运行不会因重试或跳转自动再次调用。服务重启不会重放中断任务；用户主动重新运行仍会产生新调用，应先核对之前的外部结果。

`runtime/tests/test_workflow_mcp.py` 使用独立 stdio MCP 子进程检查协议调用、类型传递、契约变化、断开连接及重复写入防护。它是手工定义流程的集成测试，不替代真实模型对话验收。

MCP 步骤可以设置 `execution.forEach`，完整引用前序步骤的 JSON 数组；参数中 `${item}` 或 `${item.字段}` 绑定当前元素。执行器顺序调用，按声明的 `pointer` 提取每项返回，最终输出为同序数组。空数组不会调用远程工具，仍产生 `[]` 交给后续报告步骤。每项调用记录包含序号、总数和真实响应；任何写入或写入后处理失败都会停止，不重复已发起的写入。

Python/命令步骤可声明 `{ "id": "items", "label": "待处理数据", "kind": "json", "path": "items.json" }`。脚本仍写入 `LOOPS_CONTEXT.outputs.items` 的文件路径，平台检查有效 JSON 后将解析结果传给下一步。省略 `kind` 的旧输出仍传递文件路径。

AI 搭建不再以整轮 3 分钟作为中断条件：单次模型请求 30 秒没有有效文本、思考或工具参数增量时提示等待，连续 60 秒无进展判定超时；持续有进展的多轮搭建可以继续，整轮保留 15 分钟上限和手动停止。每个模型请求对超时、临时网络故障与可重试服务错误最多重试 5 次（首次请求之外），重试间隔递增且默认最多 10 秒，服务端 Retry-After 提示最多等待 30 秒；鉴权或参数错误、手动停止不重试。重试保留已完成工具结果，只重新生成当前模型回复，失败请求中的部分工具参数不执行。处理过程显示实际步骤、工具状态、等待与重试，完成后自动折叠并显示耗时，最终回复单独展示；过程记录随对话保存。Loop 搭建请求的 HTTP 状态、响应头/首段增量耗时、字节数及结束原因记录在数据目录 `diagnostics/model-requests.jsonl`，不记录请求正文、回复正文或密钥。仅凭旧版的“回复已停止”记录无法追溯区分服务端排队与网络等待。

### 执行 Agent

创建 Loop 时直接描述需求，Loops AI 根据任务及本机可用客户端选择执行 Agent，用户可在对话中明确指定；生成流程后，流程顶部可修改默认值，智能步骤详情可选择其他 Agent 或恢复跟随流程。设置 → 通用显示本机客户端版本、可用状态与处理提示，“重新检查”刷新安装/登录变化。未配置的客户端不会被自动替换。

Codex 保留官方 Python SDK 接入，MiMo 使用本地 CLI 的 JSON 事件与会话续接；客户端适配分别位于 `runtime/loops_runtime/agent_plugins/`，通过同一插件加载器自动注册，详见 [Agent 插件协议](../runtime/AGENT_PLUGINS.md)。搭建对话模型保持独立。选择、步骤覆盖和运行实际绑定均持久化，旧 `tool: codex` 流程继续使用 Codex。详见 `../runtime/WORKFLOWS.md`。

在“设置 → 通用”可修改各执行 Agent 的默认模型，仅首次从客户端默认配置初始化，之后使用 Loops 保存的明确值；读取不到默认值时选择第一个模型和低思考强度；没有低档位时选择支持的最低档位。不修改客户端原配置，也不使用历史模型记录。对话中明确指定某个模型时，可设置流程或步骤覆盖；优先使用步骤指定，其次流程指定，再使用设置中的默认值。此设置与搭建对话的模型独立。

执行 Agent 设置以独立卡片显示模型与思考强度下拉框，从本机客户端读取可选项，修改后自动保存。切换模型时保留兼容强度，否则选择模型提供的默认档位或首个支持档位并明确保存；未提供档位的模型禁用强度选择。模型目录可见性不代表服务端额度或调用已经验证。

### CLI 任务节点

命令行节点支持 `forEach` 动态列表、零项跳过和 stdout JSON 结果传递，无需新增节点类型。使用 `kind=value, source=stdout, format=json` 声明数据产出，后续完整引用保留对象、数组等类型。原有单次命令与文件产出保持支持。命令默认可能写入，一旦启动，本次运行不自动重试或跳转重放；确认只读时声明 `effect=read`。超时与取消终止进程组，保留逐项证据。详细配置与兼容边界见 [流程契约](../runtime/WORKFLOWS.md#cli-逐项执行与-json-输出)。
